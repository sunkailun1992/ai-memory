# AI 记忆边界规范

本文件是 `ai-memory` 的核心领域规范。任何新增、修改、迁移 AI 记忆能力前必须先读本文件。

## 总体目标

`ai-memory` 统一管理 AI 体系中的记忆能力，避免 `ai`、`ai-agent`、`rag` 各自保存和检索个人事实，导致授权、脱敏、删除和索引策略不一致。

## 服务职责矩阵

| 能力 | 归属服务 | 说明 |
|---|---|---|
| 客户端登录、用户 token、患者选择 | `ai` | 业务入口和调用方身份，不在 `ai-memory` 重复实现 |
| 对话列表、抽屉历史、UI 展示消息 | `ai` | 展示历史不是模型记忆 |
| 问卷状态机、当前题、答案主记录 | `ai` | 工作流状态不能靠 LLM 记忆推进 |
| 模型推理、Prompt 组织、结构化输出 | `ai-agent` | `ai-memory` 不调用大模型下结论 |
| 短期记忆策略 | `ai-memory` | 会话摘要 + 最近消息窗口 |
| 长期记忆策略 | `ai-memory` | 患者级事实和偏好 |
| 记忆候选写入 | `ai-memory` | `ai-agent` 可提交候选，最终入库由本服务判定 |
| 记忆召回 | `ai-memory` | 按授权、患者、租户、用途和 token 限制返回上下文 |
| 公共知识库 RAG | `rag` | 医学指南、FAQ、产品文档、知识切片 |
| Qdrant 长记忆索引 | `ai-memory` | 仅派生索引，可由 MySQL 重建 |
| Qdrant 知识库索引 | `rag` | 公共知识库索引，不混入患者个人记忆 |

## 短期记忆

短期记忆以 conversation/thread 为作用域，用于维持当前会话连续性。

必须满足：

- 使用最近原文消息窗口 + 滚动摘要。
- 必须保留时序。
- 必须可清空当前会话记忆。
- 必须限制最大消息条数、时间窗口和 token 预算。
- 不使用 Qdrant 作为主存。

可以使用：

- MySQL 保存窗口和摘要。
- Redis 缓存热点会话短摘要。

禁止：

- 把展示历史表当成模型短记忆。
- 把短记忆直接写入长期患者事实。
- 只靠向量相似度恢复当前会话上下文。

## 长期记忆

长期记忆以患者/用户 namespace 为作用域，用于跨会话复用稳定事实。

必须满足：

- 以 `patientId + sourceTenantId` 隔离。
- 保存来源、来源业务 ID、置信度、发生时间、写入时间、状态、授权范围。
- 支持 upsert、归档、撤销、删除、脱敏。
- MySQL 是权威库。
- Qdrant 是派生索引，必须可从 MySQL 重建。

典型类型：

- `questionnaire_summary`：问卷完成摘要。
- `questionnaire_answer`：问卷关键答案事实。
- `patient_preference`：用户偏好。
- `health_signal`：症状、病史、过敏等健康线索。
- `care_context`：随访、就医沟通、报告解读上下文。

禁止：

- 把未经确认的模型推测直接写成事实。
- 把公共医学知识写入患者长期记忆。
- 删除 MySQL 事实后保留可召回的 Qdrant point。

## 候选记忆写入

`ai-agent` 可以提交候选记忆，但不能直接写最终事实表。

候选写入必须包含：

- 调用方：`ai`、`ai-agent`、其它 agent。
- 作用域：患者 ID、来源租户 ID、会话 ID。
- 来源：问卷、普通对话、报告、人工确认、外部系统。
- 记忆类型、标题、内容、结构化 facts。
- 置信度和是否需要人工确认。

`ai-memory` 必须执行：

- 授权校验。
- 租户隔离校验。
- 敏感字段识别和脱敏策略。
- 幂等合并。
- 低置信度拦截或进入待确认。
- 写入审计。

## 召回策略

召回请求必须声明：

- `patientId`
- `sourceTenantId`
- `conversationId`
- `query`
- `purpose`
- `caller`
- `maxItems`
- `maxTokens`

返回必须包含：

- 可注入模型的上下文文本。
- 每条记忆的来源、置信度、发生时间、状态。
- 可追溯 ID。
- 是否命中 Qdrant、SQL、缓存。

召回必须遵守：

- 默认最小必要原则。
- 默认不返回完整敏感明文。
- 删除/归档/撤销的记忆不得召回。
- Qdrant 命中后必须回查 MySQL 权威状态。

## Qdrant 规范

Qdrant 只做长期记忆语义索引，不做权威存储。

必须满足：

- collection 维度和 embedding 模型一致。
- point payload 不保存不可恢复的唯一事实。
- point ID 可追溯到 MySQL 记忆 ID。
- 索引失败不阻断主链路。
- MySQL 删除、归档、脱敏后必须同步删除或更新 point。

短期记忆不走 Qdrant。

## Redis 规范

Redis 只做缓存和协调，不做权威库。

可用场景：

- 热点患者记忆召回缓存。
- 会话短摘要缓存。
- 候选记忆幂等锁。
- Qdrant 索引任务锁。
- 删除/重建索引的短期状态。

Redis key 必须包含服务前缀、环境、租户、患者或会话 ID，避免串数据。

## RAG 边界

`rag` 是公共知识检索服务，不存患者个人记忆。

可以进入 `rag`：

- 医学指南。
- 公司 FAQ。
- 产品文档。
- 问卷解释说明。
- 报告解读知识。

不能进入 `rag`：

- 患者身份信息。
- 患者问卷答案。
- 患者历史症状。
- 用户偏好和私人咨询结论。

## 删除、归档、脱敏

删除必须覆盖：

- MySQL 权威事实。
- Qdrant 派生 point。
- Redis 缓存。
- 异步任务队列中未执行的索引任务。

归档必须：

- 不参与默认召回。
- 保留审计和来源。
- 支持合规查询。

脱敏必须：

- 区分存储脱敏、返回脱敏和日志脱敏。
- 普通召回不返回证件号、手机号、详细地址等完整明文。
- 管理或合规接口必须有单独权限和审计。

## 与现有 ai 原型的迁移关系

当前 `ai` 中的 memory 原型可以作为第一版数据结构参考，但最终应迁移到 `ai-memory`：

- `ai_chat_memory` → 短期原文窗口。
- `ai_chat_memory_summary` → 短期滚动摘要。
- `ai_patient_memory` → 长期患者事实。

迁移完成后，`ai` 和 `ai-agent` 都应通过 `ai-memory` API/RPC 调用，不再直接操作这些表。
