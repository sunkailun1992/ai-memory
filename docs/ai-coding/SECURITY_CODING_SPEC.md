# AI 记忆服务安全规范

## 鉴权和授权

- 所有记忆读写、召回、删除、归档、脱敏和重建索引接口必须有明确权限边界。
- 登录态和租户上下文优先复用 `utils` 统一认证能力。
- 召回不能只校验用户已登录，必须校验患者归属、来源租户、调用方和用途。
- 管理端查看、导出、脱敏前明文查看必须使用更高权限并写审计。

## 租户和患者隔离

- 长期记忆默认按 `patientId + sourceTenantId` 隔离。
- 来源租户 ID 是业务隔离字段，不能用 Kellen 自身默认租户替代。
- 跨租户召回默认禁止；确需跨租户必须有明确授权和审计。

## 隐私和脱敏

- 手机号、证件号、详细地址、报告正文、完整对话、附件 URL 等默认敏感。
- 普通召回默认返回最小必要摘要，不返回完整敏感明文。
- 日志、异常、审计摘要和模型调试输出不得写完整敏感明文。
- 删除、归档、脱敏必须同步处理 MySQL、Qdrant、Redis 和未执行任务。

## Qdrant 安全

- Qdrant 只保存派生索引，不保存唯一事实。
- Qdrant payload 不放不可控敏感明文。
- Qdrant 命中后必须回查 MySQL，确认状态、权限和脱敏策略。
- MySQL 事实删除或归档后，对应 point 必须删除或变更为不可召回。

## 候选记忆安全

- `ai-agent` 只能提交候选记忆，不能直接形成最终长期事实。
- 低置信度、模型推测、未授权来源必须进入待确认或直接拒绝。
- 候选写入必须记录来源、调用方、会话、患者、租户和原始依据摘要。

## 日志和审计

- 安全日志应包含时间、租户、患者、调用方、接口、目标资源、结果、原因和 traceId。
- 不得记录完整 Prompt、完整用户输入、完整模型输出和完整隐私字段。
- 高风险治理动作必须可追溯：删除、归档、脱敏、重建索引、批量导出。

## 测试要求

- 覆盖跨租户访问拒绝。
- 覆盖非本人患者访问拒绝。
- 覆盖删除后不可召回。
- 覆盖归档后默认不可召回。
- 覆盖 Qdrant 命中但 MySQL 状态不可用时拒绝返回。
- 覆盖日志和响应不包含敏感明文。
